## 1. 文档职责

本文档定义 Quick-A、Quick-B、Listing 三种商品营销图片制作模式的：

- 业务目标与适用场景
- 运营输入
- 商品与营销信息来源
- 信息使用权限
- 制作及人工审核流程
- 异常与关键问题处理
- 业务验收边界

本文件定义业务行为，不规定 Prompt、模型调用次数、Agent 或技术架构。

## 2. 三模式共同业务对象

### 2.1 实际销售商品

实际准备销售的目标商品。

运营提供的商品图片是最终成图外观、可见结构及配件的重要依据。

营销参考图不得无依据覆盖实际商品外观。

### 2.2 图片制作任务

围绕一款实际销售商品制作一组营销图片。

任务包含：

- 实际商品素材
- 参考营销或设计素材
- 运营整体要求
- 各图位的制作条件
- 生成及修改结果
- 审核和历史记录

### 2.3 图片图位

当前确认的图位包括：

- 主图
- 尺寸图
- 对比图
- 卖点图
- 使用场景图

主图、尺寸图和对比图各最多一个；卖点图、使用场景图可按需增加或删除。

每个图位允许独立设置参考、输出尺寸及可选要求。

内部图位名称不自动代表特定电商平台的发布规范。

### 2.4 参考图片

目前由运营人工寻找、筛选及上传。

一组参考图通常来自同一个商品链接，因此原有视觉风格一般比较一致。

当前业务以运营选定的参考为起点，不要求自动采集或强制重新设计整组风格。

### 2.5 运营要求

包括整体制作要求、逐图要求和生成后的修改意见。

具体继承、覆盖和版本规则由 `02_INTENT_AND_CONTEXT_RULES.md` 定义。

## 3. Quick-A｜同款快速改版

**状态：OPERATOR_CONFIRMED**

### 3.1 业务目标

基于同款、同配置商品的营销参考图片，重新设计营销图，保持适用营销信息及实际销售商品外观。

重点是差异化视觉表达，不是逐像素复制参考。

### 3.2 运营输入

- 实际销售商品图片
- 同款同配置商品的营销参考图片
- 可选整体及逐图要求

不要求额外提供完整 Listing。

### 3.3 信息权限

实际商品图片决定最终可见外观及配件。

营销参考图提供原有营销主题、适用卖点、参数和设计表达。

选择 Quick-A 表示运营采用同款同配置的业务前提，不应因非关键视觉差异反复要求重新确认商品关系。

参考营销宣称不自动代表独立核验的商品事实。

### 3.4 业务流程

1. 运营选择实际商品、参考图及待制作图位。
2. 系统根据参考营销信息及实际商品外观制作差异化候选图。
3. 可以合理聚焦部分适用卖点，但不得静默删除运营指定的必保留内容。
4. 运营检查图片并提出局部修改、接受或拒绝。
5. 满意后 Pass，保留版本和修改历史。

### 3.5 主要失败

- 实际商品外观或配件被改变
- 参考商品主体错误进入成图
- 适用营销卖点丢失或失真
- 参数或比较关系被错误改变
- 修改影响已经认可的其他内容
- 多轮生成偏离原有营销及视觉方向

## 4. Quick-B｜换主体快速改版

**状态：OPERATOR_CONFIRMED**

### 4.1 业务目标

基于外观不同的商品营销参考，保留适用营销内容与设计表达，并将参考商品主体和相关细节替换为实际销售商品。

### 4.2 运营输入

- 实际销售商品图片
- 外观不同的营销参考图片
- 可选整体及逐图要求

不要求额外提供完整 Listing。

### 4.3 信息权限

运营选择参考图时，默认认为其中的营销卖点和规格适用于目标商品。

这一选择构成业务上的默认适用声明，不代表相关性能已经独立检测认证。

系统原则上可以沿用参考营销信息，不需要制作前逐项要求运营确认。

若发现与实际商品存在明确、重要的配置或参数冲突，应对受影响内容定点处理。

### 4.4 商品替换要求

实际商品图片决定最终外观与配件。

参考商品必须从需要替换的区域中完整移除，包括：

- 主体展示
- 商品局部特写
- 与商品有关的配件
- 相关场景中的商品细节

不得把参考商品和实际商品的外观组合成不存在的商品。

### 4.5 业务流程

1. 运营提供实际商品图片与选定参考图。
2. 系统默认参考营销信息适用，并完成商品主体与相关细节替换。
3. 生成候选图片。
4. 运营检查并通常进行少量局部修改。
5. 满意后 Pass，保留历史。

默认不增加制作前逐条卖点确认环节。

### 4.6 主要失败

- 主体替换不完整
- 局部特写保留参考商品
- 实际商品配件与参考商品配件混合
- 适用营销卖点被无依据改变
- 成图出现明确不符合目标商品的内容
- 后续修改重新引入参考主体

## 5. Listing｜商品资料制图

**状态：OPERATOR_CONFIRMED — V0.3 重点更新**

### 5.1 业务目标

以运营提供的商品资料和实际商品图片为主要依据，制作一组能够准确表达商品卖点、功能、特点及营销目标的图片。

参考图片主要用于视觉表达，而不是直接决定商品事实。

### 5.2 运营输入

- 实际销售商品图片
- Listing、商品描述、卖点、参数或其他相关文字资料
- 可选设计参考图片
- 可选整体及逐图制作要求

具体资料格式和最低输入要求仍待结合真实案例明确。

### 5.3 信息权限

**实际商品图片**

提供商品可见外观、结构及配件依据。

**运营商品资料**

提供主要商品信息、适用卖点、功能、参数及营销内容。

**设计参考图片**

主要提供设计风格、版式、构图、场景和卖点视觉表达方式。

参考图出现但未获得运营商品资料支持的额外商品信息，不能自动继承。

商品资料与商品可见结构之间若有重要矛盾，应提出具体问题，由运营处理。

### 5.4 制作流程：只确认关键问题，其余直接生成

`OPERATOR_CONFIRMED`

**步骤 1：运营提交资料**

运营提供实际商品素材、文字商品资料，以及可选参考和制作要求。

**步骤 2：系统根据资料确定制作内容**

系统依据运营商品资料、当前图位及参考设计，选择本图应表达的内容和视觉方式。

系统应保持商品事实、卖点和运营要求的一致性。

不要求运营预先审阅每张图片的完整制作方案。

**步骤 3：处理影响制作的关键问题**

原则上直接制作。

只有发现真正影响当前图片制作、且不能安全绕开的重要问题时，才向运营提出具体确认。

典型问题包括：

- 运营商品资料与实际商品可见结构存在明显且重要的矛盾。
- 关键型号、参数或配置出现互相冲突的信息。
- 某项运营指定必须展示的内容缺少必要依据，无法准确表达。
- 缺失的信息直接影响本图必须表达的关键内容。

以上是候选关键问题类型，不表示每个未知事项均需确认。

处理原则：

1. 明确问题涉及的商品信息、图位及影响。
2. 不自行编造缺失事实。
3. 能够安全继续的其他图位或内容，不因无关问题全部阻断。
4. 对无法准确处理的关键内容，交运营决定。
5. 不新增默认的完整 Planning 人工审批步骤。

**步骤 4：生成候选图片**

不存在影响制作的关键问题，或相关问题已处理时，系统直接生成候选图片。

系统可以自行安排各图位的内容重点，但不得超出运营提供的商品信息权限。

**步骤 5：运营审核与局部修改**

运营检查：

- 商品外观
- 商品事实
- 营销卖点
- 文字与视觉表达
- 整体设计质量

发现问题后提出修改意见。

修改应围绕运营反馈展开，尽量保持已经认可的其他内容。

**步骤 6：Pass 与交付**

运营认可后标记 Pass，并保留生成、修改和审核历史。

### 5.5 生图前人工确认边界

`OPERATOR_CONFIRMED`

Listing 不采用“所有图片必须先确认完整方案再生图”的默认流程。

人工确认主要针对：

- 直接影响制作的关键商品事实矛盾。
- 不能自行推定的关键参数或配置。
- 其他会导致本图产生明显错误且无法安全继续的问题。

一般的卖点选择、内容组织、版式建议和视觉表达，不要求运营每次提前审批。

**直接生成不等于可以擅自创造商品事实，也不等于取消生成后的人工审核。**

### 5.6 主要失败

- 创造运营未提供或缺乏依据的商品功能、参数、适用范围、认证
- 错误继承视觉参考中的其他商品信息
- 忽视运营要求保留的内容
- 商品文字与实际外观冲突
- 图包卖点重复、遗漏或表达失当
- 不必要的制作前确认打断运营工作
- 生成后修改导致新的事实或设计偏移

### 5.7 验收重点

- 商品资料正确使用
- 商品外观与真实配置一致
- 营销内容没有无依据扩写
- 各图位内容安排合理
- 关键问题处理正确
- 无不必要的制作前阻断
- 运营能够快速修改并最终 Pass

## 6. 三模式共同的生成、修改和审核

### 6.1 生成

系统依据当前模式的信息权限、实际商品素材、选定参考及运营要求生成候选图片。

生成成功不代表业务验收通过。

### 6.2 修改

运营可以对某张候选图片提出修改意见。

修改应围绕指定要求展开，尽可能保持未要求改变的商品、卖点及已认可设计内容。

### 6.3 审核

运营可以查看、修改、拒绝或接受候选图片。

系统不得将模型自评直接作为运营 Pass。

### 6.4 历史与交付

保留原始素材、参考图、生成结果、修改反馈及审核历史。

新一次生成或修改不得静默覆盖已通过版本。

### 6.5 尺寸图专项规则

三种模式统一遵守：

未提供运营确认且已标注目标商品真实尺寸的专用白底素材，不制作尺寸图。

不得根据参考图片推断或复制目标商品尺寸。

## 7. 跨模式关键问题处理

`OPERATOR_CONFIRMED / PROPOSED`

| 情况 | 业务原则 |
|---|---|
| 实际商品与参考图颜色、视角不同 | 保持实际商品外观，不自动改变业务模式 |
| 商品图片未展示某项功能 | 不直接判定该功能不存在 |
| Quick-A 同款参考营销信息 | 按同款业务前提处理适用信息 |
| Quick-B 参考营销信息 | 运营选图默认适用，明确重大冲突定点处理 |
| Listing 参考额外卖点 | 没有运营商品资料支持时不自动继承 |
| Listing 商品文字与外观冲突 | 影响当前图制作的关键问题交运营处理 |
| 普通未知或非关键疑点 | 不默认阻断整组制作 |
| 核心数字、型号及比较关系不明确 | 不擅自推断、补全或修改 |
| 本图选择不展示某卖点 | 不等于该卖点不适用于商品 |
| 修改破坏已认可内容 | 作为修改问题记录，由运营审核 |

## 8. 三模式业务流程对照

| 事项 | Quick-A | Quick-B | Listing |
|---|---|---|---|
| 初始营销依据 | 同款营销参考 | 默认适用的营销参考 | 运营商品资料 |
| 视觉依据 | 参考设计 | 参考设计 | 可选设计参考 |
| 商品外观 | 实售商品 | 实售商品 | 实售商品 |
| 默认制作方式 | 直接生成候选 | 直接生成候选 | **关键问题处理后直接生成** |
| 默认逐项卖点确认 | 不要求 | 不要求 | 不要求 |
| 默认完整方案确认 | 不要求 | 不要求 | 不要求 |
| 运营审核 | 生成后 | 生成后 | 生成后 |
| 修改与 Pass | 支持 | 支持 | 支持 |

此表定义业务操作方式，不规定 AI 内部实现是否需要理解、规划或校验步骤。
