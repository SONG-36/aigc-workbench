## 1. 文档目的

使用真实商品营销图制作案例，验证三种业务模式是否真正解决运营问题。

本文件重点记录：

1. 运营提供什么。
2. 希望系统完成什么。
3. 哪些结果不可接受。
4. 运营如何决定修改或 Pass。
5. 实际执行后发现什么问题。

区分：

- `OPERATOR_CONFIRMED`：运营已经确认的业务前提。
- `OBSERVED`：已有资料或实验实际支持的记录。
- `PROPOSED_ACCEPTANCE`：建议的验收标准，待运营检验。
- `NOT_TESTED`：尚未完成真实成图或验收。

不把工程测试通过、模型响应成功或 AI 自评当成业务验收。

## 2. Case A01｜Quick-A：同款商品营销图差异化改版

### 2.1 已有真实资料

`OBSERVED / OPERATOR_CONFIRMED`

历史任务：

`7606855070114516a22f2b2d2b866143`

- 目标商品：黑色汽车电路测试仪。
- 实际商品素材：`product_001`。
- 营销参考：`reference_001`，展示蓝色主体的汽车维修营销图。
- 业务模式：Quick-A，运营选择意味着同款、同配置的业务前提。
- 当前示例图位：主图，1024×1536。
- 已有真实商品理解、参考理解、信息整合及单图制作决策结果。

当前没有该新链路的最终成图验收结果。

### 2.2 运营期望

`PROPOSED_ACCEPTANCE`

系统应：

- 保持实际销售商品的黑色主体、真实结构和配件。
- 参考原营销图的汽车维修主题、适用卖点及视觉表达。
- 实现合理的营销视觉改版，而不是机械复制参考。
- 正确处理线缆、夹子、探针等真实商品细节。
- 不无依据改变数字、型号、功能或营销信息。
- 遵守运营明确提出的整体及单图要求。

允许根据当前图片目标聚焦部分适用卖点，不要求全部原文同时展示。

### 2.3 不可接受的结果

- 黑色实售商品被错误生成成蓝色参考主体。
- 真实商品的重要部件或连接关系发生错误。
- 编造电压、测量结果或其他商品性能。
- 原始关键卖点被错误改写。
- 生成内容与已确认的商品配置明显不符。

### 2.4 人工验收

运营检查商品外观、营销信息、差异化设计及整体视觉质量。

未达到要求时提出修改；达到要求后 Pass。

**实际验收状态：NOT_TESTED。**

## 3. Case B01｜Quick-B：不同外观商品主体替换

### 3.1 已有案例依据

`OBSERVED / INCOMPLETE CASE`

历史业务反馈中，存在参考商品主体未被正确替换的失败类型。

但目前尚未在本业务基线中绑定一组完整、可复核的目标商品图、参考图、生成图和运营评价。

本节先定义业务验收要求，不虚构具体 SKU 或生成结果。

### 3.2 运营输入与前提

`OPERATOR_CONFIRMED`

运营提供：

- 实际销售商品图。
- 外观不同的商品营销参考图。
- 可选整体及逐图要求。

运营选取参考时，默认认为参考营销信息适用于目标商品。

### 3.3 运营期望

`PROPOSED_ACCEPTANCE`

系统应：

- 用实际销售商品完整替换参考商品主体。
- 同步处理涉及参考商品的局部特写和配件。
- 保留适用的营销主题及卖点表达。
- 借鉴参考的合理设计风格。
- 不组合两种商品的外观及不存在的配件。
- 支持运营生成后进行局部修改。

### 3.4 不可接受的结果

- 主体换了，但局部特写仍是参考商品。
- 商品主体或配件混合了两种商品的外观。
- 实际商品重要结构缺失或被改变。
- 参考中的营销信息被无依据修改。
- 局部修改后重新出现参考商品主体。

### 3.5 人工验收

运营重点检查商品身份、主体替换完整性、配件、卖点及设计质量。

**完整案例状态：PENDING REAL SAMPLE。**

需要补充实际商品图、参考图及至少一张生成结果，才能形成可复核的真实验收记录。

## 4. Case L01｜Listing：商品资料驱动营销图制作

### 4.1 已有真实资料

`OBSERVED — 已记录业务案例`

历史任务：

`43889e73c53c462da86216ed42f0a1ec`

- 商品：洗车设备。
- 已记录营销参考：`reference_002`。
- 历史讨论涉及 revision 3 的制作资料。
- 商品资料包含五种喷射模式：0°、15°、25°、40°、泡沫。
- 还包括三档水压、三档水量及清洗、浇灌、泡沫等应用场景。
- 已识别的风险包括错误组合喷壶与水枪结构。

这些内容属于已有运营案例资料，不代表相应性能已被独立检测。

### 4.2 运营期望

`PROPOSED_ACCEPTANCE`

系统应：

- 以运营提供的商品资料决定营销内容。
- 使用真实商品图保持外观和配置。
- 正确表达被选中的喷射模式、参数及应用场景。
- 将设计参考主要用于视觉表达。
- 不继承缺乏目标商品资料支持的参考商品卖点。
- 正确处理喷壶、水枪及相关结构关系。
- 根据不同图位合理分配营销信息。
- 只有关键商品信息冲突影响制作时才向运营确认。

### 4.3 不可接受的结果

- 五种喷射模式的数字或含义被修改。
- 编造资料中不存在的性能或数值。
- 错误组合喷壶和水枪，生成不存在的商品结构。
- 将参考图其他商品的参数作为目标商品事实。
- 重要卖点被无依据删除或改变含义。
- 非关键未知导致整个图包无法继续制作。

### 4.4 人工验收

运营检查商品结构、功能文案、参数、图位内容和整体设计。

发现关键事实错误时不能直接 Pass。

**实际验收状态：NOT TESTED / BUSINESS ACCEPTANCE NOT ESTABLISHED。**

## 5. 三种模式共同的修改验收

`OPERATOR_CONFIRMED / PROPOSED_ACCEPTANCE`

例如：

运营已有一张候选图，要求：

“把标题字号调大，其他内容保持不变。”

验收时需要同时检查：

1. 标题是否按照要求改变。
2. 商品身份、外观、配件是否保持。
3. 未要求改变的卖点、背景和布局是否保持。
4. 是否产生新的错误。
5. 运营是否满意。

**只完成目标修改，但破坏其他重要内容，不属于合格的修改结果。**

修改默认以运营当前选中的图片版本为基础。

历史修改文字不需要全部重新执行；已体现在基础图片中的有效修改应尽量保持。

## 6. Pass 与有效交付版本验收

`OPERATOR_CONFIRMED`

例如 V3 已 Pass，运营从 V3 创建 V4：

- V4 未 Pass 时，V3 仍是当前有效交付版本。
- V4 失败或被拒绝，不影响 V3。
- V4 被运营 Pass 后，成为当前有效交付版本。
- V3 保留为历史 Pass。
- 不允许静默覆盖旧图片或历史审核记录。

新的整体要求不自动修改或使已经 Pass 的图片失效。

## 7. 通用验收判断

`PROPOSED_ACCEPTANCE`

| 验收维度 | 重点检查 |
|---|---|
| 商品保真 | 主体、颜色、结构与配件是否正确 |
| 内容准确 | 卖点、参数、文字及语义是否正确 |
| 参考执行 | 是否遵守对应模式的营销与设计依据 |
| 图包协调 | 是否遵守有效的整体制作要求 |
| 修改稳定 | 是否实现目标修改并避免非目标变化 |
| 版本保护 | 是否使用正确基础版本、保留旧 Pass |
| 视觉质量 | 排版、层级、可读性及商业呈现是否满足运营需要 |

### 处理结果

- **Pass：** 运营认可当前具体图片版本。
- **Revision：** 图片存在可修改问题，运营提出修改要求。
- **Reject：** 当前候选不满足业务要求，不能直接采用。

具体评分权重、通过率和成本阈值尚未通过真实运营样本确定。

不能以 AI 自评代替运营决定。
