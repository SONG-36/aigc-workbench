## 2. F00 — 工程准备及旧 UI 基线

**目标：** 确认旧 UI 实际来源，核对主要页面布局和核心操作路径，明确保留、按业务调整及排除项，并形成 F01 工程建设前置检查结果。

**范围：** 读取 06 / I01 / I02 及必要业务依据；确认已批准业务规则；执行 [I01 UI BASELINE CHECKPOINT](./I01_FRONTEND_WORKBENCH.md#ui-baseline-checkpoint)，对照 [继承矩阵](./I01_FRONTEND_WORKBENCH.md#ui-inheritance-matrix) 核对真实页面、区域关系及用户路径，记录 HEAD、工作区状态和未提交来源版本。旧仓保持只读，不因基线核对安装依赖、写业务数据或触发付费模型。

**本轮前置检查结果：**

- 已核对新旧仓分支、HEAD、工作区和现有文档；旧仓未提交及未跟踪资产与已提交来源分开记录。
- 三模式权限、尺寸图条件、有效要求、运营选定基础版本及 Pass 保护仍以上位业务文档为准；旧 Listing 强制参考、完整 Planning 预审等行为继续排除。
- 已利用现有环境取得部分真实页面及本地交互证据，详见 I01 §8.3；没有启动服务、保存任务或执行模型操作。
- **UI Baseline NOT VISUALLY VERIFIED**：带数据只读预览加载失败，候选、历史版本、草稿保护、Pass / Reject 和 Inspector 内容的完整视觉核对尚未完成。不能将部分截图扩展为全工作台验收通过。

真实截图应注明页面、运行环境及对应来源，区分实际截图与设计示意。截图含商业或其他敏感信息时，未经检查不提交 Git。环境不可用时记录原因、可检查材料和后续验证方法，不擅自用新设计替代旧界面。

## 3. F01 — 整体工程框架搭建

**目标：** 建立整体可运行的模块化单体工程基础，明确代码结构、职责、依赖和 UI Shell，再接通后续真实业务与 AI 能力；不以仅启动应用或 API 连通作为本阶段全部成果。

**工程方向：** React + TypeScript + Vite、Python + FastAPI、前后端分离、服务器掌握业务状态、最小测试与开发环境；初期 SQLite 和本地素材存储仍为候选。Context / AI / Runtime 的逻辑边界沿用 I02，不新增架构模块。技术方向如有实际不可行原因，报告依据，不擅自换成其他架构；本计划不把未实施方案升级为工程验证通过。

**实施范围：**

1. 前端工程启动与路由，具有可解释的页面入口。
2. 基于已核实旧工作台设计的 UI Shell，保留有效信息层次和操作路径；尚未接通的能力明确不可用。
3. 后端 API 与 Application 基础，边界和实际调用关系清楚。
4. 支撑本阶段真实操作所需的 Domain 与持久化基础，服务器拥有持久业务状态权威。
5. 明确 Context、AI、Runtime 的模块归属；暂未实现的能力在工程边界文档中说明归属即可，不创建空类或假实现来凑齐目录。
6. 仅引入实际使用到的依赖、接口和必要隔离，不预建完整 Repository / Adapter / Registry 体系。
7. 至少一条最小真实业务操作可以持久化、读取并恢复，而非仅内存返回或静态占位。
8. 基础自动化测试和前后端实际运行验证，不以模拟连通代替真实运行。
9. 简洁的开发、启动、测试及调试说明，能沿真实操作定位关键文件和调用路径。

具体最小业务操作必须在 F01 开发开始前，根据已确认业务契约和 I02 既有用例收束范围及验收；本轮不创造新业务操作、规则、数据库字段或 API。只设计这条路径实际需要的最小持久化与接口，不提前完整设计全部数据库和 API。

**明确排除：** 完整三模式、完整图位操作、真实 AI 调用、图像生成、通用 Agent、大型 Workflow、无必要的复杂抽象，以及将未实现功能伪装成可用。F01 不提前完成 S01 的完整素材闭环或 S02 / S03 能力链路。

**验收：**

- 前后端真实运行，实际 API 请求与响应连通，模块归属及依赖方向清晰。
- UI Shell 与已核实的旧 UI 基线一致，显著差异有理由并经过真实浏览器对照，不用全新简陋页面替代既有产品设计。
- 至少一条已收束的最小真实业务操作能保存、查询和恢复；刷新或重新读取后由服务器恢复持久状态。
- 相关确定性测试通过；能够说明页面 → API → Application → Domain / Persistence → 页面恢复的实际调用路径及关键文件。
- 没有大量空类、空接口、假功能或重复业务真相；未实现的 AI 能力不冒充完成。
- 必要启动、测试、调试方法清楚，未完成和失败项如实报告，沿用第 8 节交付纪律。

**UI 基线限制：** 当前未完成完整视觉基线，F01 可以准备非 UI 工程基础，但正式 UI 迁移不能据猜测完成。待相应区域基线核实后再迁移和浏览器对照；限制未解除时不能声称 F01 整体验收通过。迁移后的新 UI 对照随对应功能交付完成，不反过来要求先实现完整新 UI 才记录旧仓基线。

## 4. S01 — Quick-A 真实业务素材闭环

**目标：** 基于旧仓有效工作台交互，实现真实素材保存与恢复。

**范围：** Quick-A 入口、实际商品图与营销参考上传、最小真实图位、Task / Asset / Slot，以及服务端保存和工作台恢复。

**UI 要求：** 尽量沿用已核对的旧工作台有效布局和操作路径。允许分批接通区域，未实现的生成、修改、审核等操作必须明确不可用；不得无故以全新简陋上传页取代产品工作台，也不得展示虚假完成状态。

**排除：** AI 调用，以及为完成首个素材闭环而提前实现后续制作能力。三模式业务定义仍引用上位文档，S01 范围不改变 Quick-B 或 Listing 规则。

**验收：**

- 实际文件已保存并可重新读取，不以浏览器临时预览充当持久素材。
- 刷新或重新打开任务后，Task / Asset / Slot、图位设置及参考关系正确恢复。
- 图位身份与参考资产身份分开，操作不串位，业务状态由服务器管理。
- 相关 API / Domain 确定性测试通过。
- 完成真实浏览器上传、保存和恢复操作，并对照旧 UI 基线记录实际差异。
- 本切片不调用 AI。

## 5. S02 — C01 确定性执行链路

**目标：** 复用 S01 的真实业务对象与素材身份，验证 Context、Run、测试适配器和 Evidence 的衔接，不另建脱离产品的商品事实系统。

**范围：** 经受控开发入口，按 I02 的 C01 职责准备实际 Context，建立可追踪执行身份，使用测试适配器，保存实际测试输入、模拟输出及执行记录，并可回查。

**排除：** 付费模型调用、C02～C08 全量实现、图片生成及把能力编号当成固定调用流水线。

**验收：** 素材和 Context 来源可核对；Run 与业务对象正确关联；成功、失败及查询路径有相关确定性测试。测试适配器输出明确标为测试 / 模拟结果，不能冒充真实模型理解或真实供应商响应。Runtime、Evidence 的具体责任引用 I02，不在本计划重定义。

## 6. S03 — C01 真实理解实验

**目标：** 受控调用真实多模态模型，保存实际 Context、原始响应与人工评价，检验商品视觉理解。

**复用：** 沿用 S01 / S02 的业务对象、素材、Context、Runtime 和 Evidence 边界；独立开发入口不表示正式运营每次必须单独调用 C01。

**真实调用前必须明确：** 指定模型及凭证可用性、调用授权、调用次数和预算上限、超时与失败处理、真实样本及人工评价方法。尚未明确这些条件时不得执行付费调用；结果未知时先核对原请求，不盲目自动付费重试。

**验收：** 能回查实际商品素材身份、实际 Context、模型与指令配置、真实原始响应和执行状态；人工对照原图记录正确、错误、推断与未知。调用成功或响应格式正确不等于理解正确，更不等于运营 Pass。

本阶段不自动开发图片生成能力，不把一次 C01 实验推广为三模式整体质量或商业收益通过。

## 8. 每个切片的 Codex 交付标准

每次开发交付至少报告：

1. 本次实际实现内容。
2. 修改的文件。
3. 主要业务调用路径。
4. 模块职责说明。
5. 测试执行结果。
6. 真实运行证据。
7. 未完成或失败的部分。
8. 是否影响旧 UI 继承基线，以及实际差异和原因。
9. Git 状态及提交信息。

| 状态维度 | 必须区分的含义 |
|---|---|
| DESIGNED | 已形成设计或计划；注明草稿 / 审核状态，不代表已实现 |
| IMPLEMENTED | 实际代码已实现；注明范围及未接通部分 |
| ENGINEERING VERIFIED | 有明确范围的测试、实际运行及证据；不替代真实 AI 或业务评价 |
| AI EVALUATED | 有真实模型输入输出、评价方法及实际结论；测试适配器不能提供此结论 |
| BUSINESS ACCEPTED | 有运营对具体结果和范围的接受依据，不从工程测试或模型成功自动推导 |

各维度分别记录，不视为自动连续晋级。正式 UI 对照需记录真实浏览器证据，模拟 DOM 测试不能替代。

代码可读性检查：不出现无必要的巨型混合职责模块；不使用跨模块隐式全局业务状态；不重复存储相互冲突的业务真相；不提前建立无实际用途的抽象框架；每个真实操作可追踪调用路径。不以文件行数作为唯一质量标准。工程边界与测试责任引用 I02，不另立第二套规则。
